## Feature A — Travel Passport (มาร์กว่าเคยไปแล้ว)

เว็บต้องรู้ว่าเราเคยไปเมืองไหนมาแล้ว **ก่อน** ที่จะแนะนำเมืองต่อไปได้

- ทุกการ์ดเมืองมีปุ่ม **“ไปมาแล้ว”** กดสลับเปิด/ปิดได้
- ในหน้า Destination Modal ก็มีปุ่มเดียวกันนี้ กดจากที่ไหนก็ได้ผลเหมือนกัน
- เมืองที่มาร์กแล้วต้องมี badge / stamp ให้เห็นชัดบนการ์ด
- ด้านบนเว็บมี **Travel Passport** สรุปว่า **ไปมาแล้วกี่เมือง** และ **Save ไว้กี่เมือง**
- ปุ่ม “ไปมาแล้ว” บนการ์ด ต้อง **ไม่เปิด Modal**
- สถานะนี้เป็นข้อมูลชั่วคราวเหมือน My Trip — Refresh แล้วเริ่มใหม่ได้ ห้ามใช้ localStorage

### ★ Visited มีชุดเดียวเท่านั้น
ทั้งเว็บต้องอ่าน/เขียนสถานะ “เคยไปแล้ว” จากตัวแปรชุดเดียวกัน
ห้ามให้เกมเก็บรายการเมืองที่เคยไปเป็นของตัวเองแยกอีกชุด
เพราะจะทำให้ตัวเลข Passport กับผลลัพธ์ของเกมไม่ตรงกัน

## Feature B — Find My Next Trip

เกมสั้น ๆ ที่ช่วยเลือก Destination ถัดไปจาก 6 เมืองเดิม

### Flow
1. **ไม่ต้องถามว่าเคยไปเมืองไหนแล้ว** — เว็บรู้อยู่แล้วจาก Feature A
2. ถามความชอบ **3 ข้อ** เท่านั้น:
   - ตอนนี้อยากได้อะไร: Food / Culture / Shopping / Nature
   - จังหวะทริป: Fast & Busy / Balanced / Slow & Relaxed
   - ระยะทริป: Weekend / 4–6 Days / Flexible
3. ตัดเมืองที่มาร์กว่า “ไปมาแล้ว” ออกจากตัวเลือกก่อน
4. ถ้าเคยไปครบทุกเมืองแล้ว จึงเลือกจากทุกเมืองได้
5. ให้คะแนนด้วย rule-based scoring จาก tags ใน `destinations-data.js`
6. แสดงผลลัพธ์เป็น **1 Destination** พร้อมเหตุผลว่าตรงกับ preference อะไร
7. ปุ่ม “ดูเมืองนี้” ต้อง **reuse Destination Modal เดิม** ห้ามสร้างแผงใหม่
8. ปุ่ม “เก็บไว้ My Trip” ต้อง reuse My Trip เดิม
9. เล่นซ้ำได้โดยไม่ต้อง Refresh

## Technical Constraints
- กฎเรื่องกล่อง FACT จาก SPEC V1 ยังใช้เหมือนเดิม
  ห้ามแต่งข้อมูล ไม่แน่ใจให้ใส่ `<ตรวจเอง>`
- rule-based JavaScript เท่านั้น
- ไม่เรียก AI API
- ไม่ใช้ backend / database / package เพิ่ม
- Feature V1 เดิมต้องยังทำงานทั้งหมด
